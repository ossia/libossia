ossia::telemetry Namespace Reference

Detailed Description

Informative data going from the execution back to the user interface.

The audio thread never allocates, never locks and never loses a peak:

  • every metering point (a tap) accumulates on its own writer thread;
  • once per publication period, the tick thread gathers all taps into one frame at a fixed slot per tap and hands it over through a triple buffer;
  • levels the interface has not read yet are merged into the next frame instead of being dropped, so the interface can read at any rate.

Slots are allocated by the interface, which pairs each index with a generation: a reader only trusts a slot whose generation it expects.
